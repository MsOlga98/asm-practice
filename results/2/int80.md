# int 0x80 — системні виклики в Linux (x86, 32-біт)

## 1. Що таке `int 0x80`

`int` — інструкція процесора x86, яка викликає **програмне переривання** з вказаним номером. Число `0x80` (128 у десятковій системі) — це номер вектора, який Linux на 32-бітній x86 використовує як **точку входу в ядро для системних викликів** (syscalls).

Навіщо це потрібно:

- Звичайна програма працює в **режимі користувача** (user mode, ring 3). Вона не може напряму працювати з диском, терміналом, мережею чи керувати процесами.
- Усе це вміє робити лише **ядро** ОС (kernel mode, ring 0). Тому, щоб вивести текст на екран, прочитати файл чи завершити роботу, програма «просить» ядро через системний виклик.
- `int 0x80` — це і є «стукіт у двері ядра».

Що відбувається під час `int 0x80`:

1. Програма кладе **номер системного виклику** в регістр `EAX`, а **аргументи** — в інші регістри.
2. Виконується `int 0x80` — процесор перемикається в режим ядра.
3. Ядро за номером з `EAX` знаходить потрібну функцію (наприклад, `sys_write`) і виконує її.
4. Результат повертається в `EAX`, процесор повертається в режим користувача, і програма продовжує роботу з наступної інструкції.

## 2. Угода про передачу параметрів (32-бітний Linux ABI)

| Регістр | Призначення |
|---------|-------------|
| `EAX`   | номер системного виклику (на вході), результат (на виході) |
| `EBX`   | 1-й аргумент |
| `ECX`   | 2-й аргумент |
| `EDX`   | 3-й аргумент |
| `ESI`   | 4-й аргумент |
| `EDI`   | 5-й аргумент |
| `EBP`   | 6-й аргумент |

Результат повертається в `EAX`. Якщо сталася помилка, повертається **від'ємне число** `-errno` (наприклад, `-2` означає «файл не знайдено»).

Стандартні файлові дескриптори: `0` — stdin (ввід), `1` — stdout (вивід), `2` — stderr (потік помилок).

## 3. Найуживаніші системні виклики

| № (`EAX`) | Назва | `EBX` | `ECX` | `EDX` | Що робить / що повертає |
|-----------|-------|-------|-------|-------|--------------------------|
| 1  | `sys_exit`   | код завершення | — | — | Завершує програму з вказаним кодом (0 — успіх) |
| 2  | `sys_fork`   | — | — | — | Створює копію процесу; повертає PID дочірнього процесу (у дочірньому — 0) |
| 3  | `sys_read`   | дескриптор (fd) | адреса буфера | кількість байтів | Читає дані з fd у буфер; повертає кількість прочитаних байтів (0 — кінець файлу) |
| 4  | `sys_write`  | дескриптор (fd) | адреса буфера | кількість байтів | Записує дані з буфера в fd; повертає кількість записаних байтів |
| 5  | `sys_open`   | адреса рядка з шляхом (закінчується нулем) | прапорці (`O_RDONLY`=0, `O_WRONLY`=1, `O_RDWR`=2, `O_CREAT`=0x40, `O_TRUNC`=0x200, `O_APPEND`=0x400) | права доступу (mode, напр. 0644 вісімково) | Відкриває файл; повертає fd |
| 6  | `sys_close`  | дескриптор (fd) | — | — | Закриває файл |
| 11 | `sys_execve` | шлях до програми | масив аргументів (argv) | масив змінних середовища (envp) | Запускає іншу програму замість поточної |
| 19 | `sys_lseek`  | дескриптор (fd) | зміщення (offset) | звідки (`SEEK_SET`=0, `SEEK_CUR`=1, `SEEK_END`=2) | Переміщує позицію читання/запису у файлі |
| 20 | `sys_getpid` | — | — | — | Повертає PID поточного процесу |
| 45 | `sys_brk`    | нова адреса кінця купи (heap) | — | — | Змінює розмір купи; з `0` повертає поточну межу |

Найчастіше в простих програмах використовують пару **`sys_write`** (вивід) та **`sys_exit`** (завершення), а для вводу — **`sys_read`**.

## 4. Приклад: «Hello, world!» (NASM, 32-біт)

```nasm
section .data
    msg db "Hello, world!", 10      ; рядок + символ нового рядка
    len equ $ - msg                 ; довжина рядка

section .text
    global _start

_start:
    ; sys_write(1, msg, len)
    mov eax, 4          ; номер виклику sys_write
    mov ebx, 1          ; fd = 1 (stdout)
    mov ecx, msg        ; адреса рядка
    mov edx, len        ; кількість байтів
    int 0x80

    ; sys_exit(0)
    mov eax, 1          ; номер виклику sys_exit
    xor ebx, ebx        ; код завершення 0
    int 0x80
```

Збірка та запуск:

```bash
nasm -f elf32 hello.asm -o hello.o
ld -m elf_i386 hello.o -o hello
./hello
```

Щоб побачити, які саме системні виклики робить програма, можна запустити `strace ./hello` — у виводі будуть `write(1, "Hello, world!\n", 14)` та `exit(0)`.

## 5. `int 0x80` і `syscall`

- `int 0x80` — **класичний (застарілий)** спосіб системних викликів у 32-бітному Linux.
- У 64-бітному Linux основний спосіб — інструкція `syscall`: інші номери викликів (`write` = 1, `read` = 0, `exit` = 60) та інші регістри (`RAX` — номер, аргументи в `RDI`, `RSI`, `RDX`, `R10`, `R8`, `R9`).
- `int 0x80` у 64-бітній системі теж працює, але через 32-бітну таблицю викликів, повільніше й з обмеженням на 32-бітні адреси, тому для нового коду його не рекомендують.
